# Data sources, ingestion, normalization and event matching

How Blueprint (NBA xFG + tracking) and official NBA records are collected for the season and combined
into one shot table. The code:

* `pipeline/ingestion/blueprint_scrape.py`, `blueprint.py`, `nba_pages.py`, `schedule.py`, `season.py`;
* `pipeline/matching/engine.py`, `court.py`, `clock.py`.

Tests: `tests/test_ingestion.py`, `tests/test_matching.py`, `tests/test_integration_oct28.py`. Data
layout and restore: [`DATA_FILES.md`](../architecture/DATA_FILES.md). The current season numbers are in
`data/reports/season/COVERAGE_REPORT.md`, regenerated by `python -m pipeline coverage-report`.

## Sources

| Source | What it provides | Where |
| --- | --- | --- |
| Blueprint game page (`nba.com/blueprint/game/<id>`) | per-shot NBA xFG, shooter/defender, contest distance/height, shot vertical, shooter speed, release time, shot clock, x/y, running score | `data/raw/blueprint/2026-27/games/<id>.csv` (+ `raw/<id>.json` and `fetch_meta.json`) |
| NBA.com game page (`/game/<away>-vs-<home>-<id>/box-score`) | play-by-play (`actionNumber`, period, clock, personId, `xLegacy`/`yLegacy`, `subType`, `shotResult`, `shotValue`, `actionId`, description, running score), box score, game header (date, status) | `data/raw/nba_pages/2026-27/<id>.next_data.json.gz` (+ `.meta.json`) |
| NBA.com games listing (`/games?date=D`) | game IDs linked on each date | `data/raw/nba_listings/2026-27/<date>.json` |
| ShotChartDetail / PlayerDashPtShots (historical) | Model A training inputs, Master pre-season priors | `data/raw/historical/` |

From this environment, `stats.nba.com` timed out and `cdn.nba.com` returned HTTP 403. The public pages
above embed the same data in their `__NEXT_DATA__` / flight payloads.

Network rules (`--allow-network` is opt-in):

* one request per page, cached with sha256 and fetch metadata, never re-downloaded once final;
* a 3.5 s delay between requests and a descriptive User-Agent;
* the run stops at once on HTTP 403/429 (`AccessRefused`) and records `stopped` in the manifest;
* no authentication, anti-bot or access controls are bypassed.

Redistribution or public hosting of NBA data, and any use of video, needs a separate licensing review.

## Season ingestion (`python -m pipeline ingest-season`)

1. **Discovery.** For every date from 2026-10-18 to the end date, read the games listing and collect
   `00226…` regular-season IDs. IDs are not chronological, so dates are never inferred from IDs.
2. **Date verification.** Each game is dated by the `gameEt` header of its own official game page,
   not by the listing. If the listing date disagrees, the official date wins and the disagreement is
   recorded (`listing_date_correct = False`; one game this season).
3. **Status per game** in `data/raw/blueprint/2026-27/season_manifest.json`:

   | Status | Meaning |
   | --- | --- |
   | `verified` | game Final, play-by-play FGA/FGM/3PA equal the box score for both teams, Blueprint fetched and matched |
   | `not_final` | game not Final; re-fetched next run |
   | `blueprint_empty` | the Blueprint page published no shot records |
   | `official_mismatch` | play-by-play disagrees with the box score; excluded |
   | `pending_fetch` / `error` | not yet fetched / parsing failed; never treated as complete |

4. **Incremental runs.** Verified games are skipped. Games from the last 2 days (`refresh_recent_days`)
   are re-fetched, because Blueprint can add shots after the final buzzer.
   `coverage-report --reverify` re-verifies everything offline from the cache.
5. **Extraction audit.** For every Blueprint page, `extract_shots` counts the shot-shaped records it
   kept and rejected, with reasons (`no_shooter`, `missing_xfg`, `xfg_out_of_range`), and the raw
   `expFieldGoalPct` mentions. A shot absent from the page is a source gap, not a parsing loss: there
   were 0 rejections this season.

## Two play-by-play formats

Game pages carry one of two play-by-play formats:

* **stats v3:** `actionType` "Made Shot"/"Missed Shot", `subType` = ShotChartDetail action type, scores
  blank on misses.
* **NGSS live** (`pbp.source == "ngss"`, e.g. 0022600088, 0022600142, 0022600144): `actionType`
  `2pt`/`3pt`, the action split into `descriptor` + `subType`, running scores on every row, and rows
  not ordered.

`nba_pages.normalize_live_actions` converts the live format to v3:

* sorts by `orderNumber`;
* maps descriptor + subType onto the 48 historical ShotChartDetail `ACTION_TYPE`s;
* sets `shotValue` and prefixes free-throw subtypes;
* derives home/visitor `location`.

`parse_game_page` records the format in `header["pbp_format"]`. Live games then matched 100% of
Blueprint records by event ID (e.g. 0022600088: 173/173).

## Official play-by-play -> ShotChartDetail schema

| ShotChartDetail field | Derived from | Validation |
| --- | --- | --- |
| `GAME_EVENT_ID` | `actionNumber` | matches Blueprint `ngss_event_id` (below) |
| `LOC_X`, `LOC_Y` | `xLegacy`, `yLegacy` | identical to Blueprint x/y on matched shots |
| `ACTION_TYPE` | `subType` (v3) or the live mapping | every value is in Model A's 48 training categories |
| `SHOT_TYPE` | `shotValue` | |
| `SHOT_MADE_FLAG` | `shotResult` (explicit field; never inferred from the score) | FGM equals the box score |
| `SHOT_DISTANCE` | `floor(hypot(LOC_X, LOC_Y) / 10)` | 100% agreement on 540,627 historical shots; PBP `shotDistance` is kept raw as `pbp_shotDistance` |
| `SHOT_ZONE_BASIC` | geometric rules in `court.py` | 99.98% agreement (the 98 disagreements are source-label inconsistencies) |
| `MINUTES_REMAINING`, `SECONDS_REMAINING` | ISO clock, truncated | |

Raw PBP fields are kept with a `pbp_` prefix.

## Coordinates and clock

* Legacy shot-chart frame: tenths of a foot, hoop at the origin, +y towards half court, baseline at
  y = -52.5. `court.court_feet` converts to the frontend frame (feet, x across [-25, 25], y from the
  baseline).
* Clocks: Blueprint `MM:SS` (whole seconds), PBP `PT11M38.00S` (tenths in the final minute), and
  ShotChartDetail integer minutes/seconds (truncated). All are parsed to seconds remaining, and
  `elapsed_s` counts from tip-off (720 s quarters, 300 s overtimes).

## Matching algorithm

Per game:

1. **Event-ID hypothesis, tested rather than assumed.** Pair Blueprint `ngss_event_id` with official
   `GAME_EVENT_ID`. A pair is accepted only if period, shooter and result agree, the clock differs
   by at most 2 s and the location by at most 3 ft.
2. **Attribute fallback** for unverified Blueprint rows. The candidates are unclaimed official shots
   with the same period, shooter and result, within the same tolerances. A unique candidate is
   accepted. With several candidates, the best is accepted only if its score beats the runner-up by
   the margin; otherwise the row is `ambiguous`.
3. **One-to-one enforcement.** If two Blueprint rows claim one official shot, both become `ambiguous`.
4. An ID pair that fails corroboration and has no fallback candidate becomes `rejected_id_conflict`.
   The official record stays in the table as an official FGA without tracking.

A 2PT/3PT disagreement does not block a match but is reported. The official classification drives
shot value and all model inputs; NBA xFG is kept as published and never invented for missing shots.

## Unified shot table

* One row per official FGA, `shot_uid = <game_id>_<GAME_EVENT_ID:04d>`.
* Flags: `in_official`, `in_blueprint`, `match_status`, `match_method`, `clock_diff_s`,
  `coord_diff_ft`, `value_agree`.
* Blueprint columns whose names collide with official ones are prefixed `bp_`.
* Provenance: `source_file`, `source_sha256` and `source_row` for Blueprint; page sha256 in
  `data/raw/nba_pages/2026-27/<id>.meta.json`.

## Season results (107 games, 2026-10-20 to 2026-11-02)

| | |
| --- | --- |
| Games verified | 107 of 107 discovered (0 not final, 0 Blueprint-empty, 0 official mismatches, 0 errors) |
| Official FGA (= box score) | 18,852 |
| Blueprint records extracted | 17,425 (0 extraction rejections) |
| Matched one-to-one | 17,389 (92.2% of official FGA), all by corroborated event ID, 0 by attribute fallback, 0 ambiguous |
| Rejected ID conflicts | 35 (shooter differs 18, result differs 12, clock > 2 s 4, location 1); left unmatched rather than forced |
| Unmatched Blueprint records | 1 |
| 2PT/3PT disagreements | 73 matched shots (official value used) |
| Missing tracking fields on matched shots | none |
| Per-game coverage | median 94.1%, min 15.7% |

**Partially published games:** 0022600143 LAL@LAC (15.7%), 0022600111 GSW@PHX (49.7%) and 0022600171
TOR@LAC (56.9%). Their official records are complete; Blueprint published only part of the shots.
They stay in the data, and their untracked attempts get the no-tracking fallback model in the
analytics exports.

**The missing shots are not random.** Excluding the three partial games, 1,170 of 18,348 official
FGA (6.4%) have no Blueprint record. They shoot 24.4% against 45.8% overall. Compared with all FGA,
they are:

* over-represented at the rim and in the paint (60% vs 47%), on tip/putbacks (9.2% vs 4.2%) and in
  the 4th quarter (33% vs 24%);
* under-represented on above-the-break threes (22% vs 32%).

So the tracked population is slightly easier and make-rich. Training and evaluation of the Master
model and the NBA xFG comparison both use only tracked shots, so the comparison is like-for-like.
Absolute calibration of any model on *all* FGA is not tested by it.

**ID conflicts:**

* `result` conflicts include Blueprint result errors confirmed by its own running score (e.g. on
  2026-10-28, `0022600133_0203`: Blueprint marks Ayton's tip-in missed, but its score rises 48→50
  and the PBP records a make).
* `player` conflicts are shooter-attribution differences between the two sources (not individually
  audited).

Official records win in both cases.
